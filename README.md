# O2C Process&Delivery Performance Analysis

โปรเจกต์วิเคราะห์กระบวนการ Order-to-Cash (O2C) และประสิทธิภาพการจัดส่งจากข้อมูลคำสั่งซื้อ E-Commerce  เพื่อค้นหาจุดคอขวดในกระบวนการ fulfillment และประเมินผลกระทบของการส่งสินค้าล่าช้าต่อความพึงพอใจของลูกค้าและรายได้ของธุรกิจ

---

## สรุปผลการวิเคราะห์และข้อค้นพบสำคัญทางธุรกิจ 

### 1. คอขวดหลักของกระบวนการ 
- คอขวดอันดับ 1 : คือช่วง Carrier Transit (`days_to_customer`) หรือเวลาที่บริษัทขนส่งนำพัสดุไปส่งถึงมือลูกค้า 
  * ใช้เวลาเฉลี่ย 9.36 วัน (มัธยฐาน 7.11 วัน) 
  * คิดเป็น 74.21% ของระยะเวลาเฉลี่ยรวมทั้งระบบ
  * ที่เปอร์เซ็นไทล์ที่ 90 (90th Percentile) ใช้เวลาสูงถึง 18.95 วัน
- คอขวดอันดับ 2 : คือช่วง Seller Dispatch (`days_to_carrier`) หรือเวลาที่ผู้ขายใช้ในการแพ็กและส่งมอบพัสดุให้บริษัทขนส่ง 
  * ใช้เวลาเฉลี่ย 2.85 วัน (มัธยฐาน 1.85 วัน, 90th Percentile 6.02 วัน)
- ขั้นตอนที่เร็วที่สุด: คือ Payment Approval (`days_to_approve`) ใช้เวลามัธยฐานเพียง 0.01 วัน (เฉลี่ย 0.40 วัน หรือ 3.19% ของเวลารวม)

### 2. อัตราการจัดส่งตรงเวลาและความแม่นยำของ SLA
- On-Time Delivery Rate ภาพรวม: อยู่ที่ 93.2% (มีคำสั่งซื้อที่ส่งล่าช้ากว่ากำหนด 6.8%)
- ความแม่นยำของโมเดลประมาณการวันส่งมอบ:
  * โมเดลเดิมของระบบมีลักษณะ Over-cautious
  * คำสั่งซื้อกว่า 91.8% ส่งถึงมือก่อนกำหนดเวลาที่ระบบแจ้งล่วงหน้า โดยเฉลี่ยส่งเร็วกว่ากำหนดถึง 11.8 วัน
  * การตั้ง SLA นานเกินความเป็นจริงช่วยให้อัตราส่งตรงเวลาดูสูง แต่ส่งผลเสียต่อ Conversion Rate บนหน้า Checkout เพราะลูกค้าอาจยกเลิกการซื้อหากเห็นระยะเวลารอคอยที่ยาวนานเกินไป

### 3. ผลกระทบของความล่าช้าต่อคะแนนรีวิว 
ความล่าช้าในการจัดส่งส่งผลกระทบต่อคะแนนรีวิวของลูกค้าอย่างมีนัยสำคัญยิ่งยวด:
- ส่งตรงเวลาหรือก่อนกำหนด: ได้คะแนนรีวิวเฉลี่ยสูงถึง 4.29 / 5.00 ดาว
- ล่าช้า 1–3 วัน: คะแนนรีวิวเฉลี่ยลดลงเหลือ 3.29 ดาว 
- ล่าช้า 4–7 วัน: คะแนนลดลงสู่โซนวิกฤตที่ 2.11 ดาว
- ล่าช้าเกิน 7 วันขึ้นไป: คะแนนรีวิวร่วงลงเหลือเพียง 1.67 – 1.72 ดาว

### 4. ข้อเสนอแนะ 
1. กำหนดวันส่งแบบยืดหยุ่นตามระยะทางจริง: เลิกใช้เกณฑ์เวลาเดียวกันทั้งประเทศ ให้แยกระหว่างส่งในจังหวัด/รัฐเดียวกัน กับการส่งข้ามรัฐระยะไกล
2. ขยายเวลาแจ้งลูกค้าในพื้นที่เข้าถึงยาก: รัฐโซนห่างไกลมีอัตราส่งช้าสูงถึง 14% – 21% ควรระบุระยะเวลาให้ตรงตามความเป็นจริง
3. ตั้งกฎคุมร้านค้าให้ส่งของไวขึ้น: บังคับให้ร้านค้าแพ็กและส่งพัสดุให้ขนส่งภายใน 48 ชั่วโมง เพื่อตัดปัญหาเวลาสะสมตั้งแต่ต้นทาง

## แนวคิดและขั้นตอนการทำ Data Pipeline (Data Engineering & Cleaning)

### 1. Data Ingestion & Schema Parsing
- แปลงคอลัมน์เวลาทั้งหมด 5 คอลัมน์ (`order_purchase_timestamp`, `order_approved_at`, `order_delivered_carrier_date`, `order_delivered_customer_date`, `order_estimated_delivery_date`) ให้เป็นชนิดข้อมูล `datetime64[ns]` เพื่อให้รองรับการคำนวณความต่างของเวลา (Time Difference)

### 2. Business Filtering & Missing Value Handling
- กรองเฉพาะคำสั่งซื้อที่มีสถานะ `order_status == 'delivered'` เนื่องจากออเดอร์ที่ถูกยกเลิก (`canceled`) หรือกำลังจัดส่ง (`shipped`) ยังไม่สิ้นสุดกระบวนการ Order-to-Delivery
- ลบแถวที่มีค่าว่าง (Missing / NaN) ใน 4 จุดเวลาหลัก เพื่อป้องกันข้อผิดพลาดทางคณิตศาสตร์ในการคำนวณ Stage Duration

### 3. Duration Feature Engineering & Data Validation
- แปลงผลต่างของเวลาให้เป็นหน่วย "วัน" โดยคำนวณผ่านค่าวินาทีรวม (`.dt.total_seconds() / 86400`)
- Data Validation: ลบแถวข้อมูลที่ระยะเวลาติดลบ ($< 0$) ซึ่งเกิดจากระบบบันทึกเวลาผิดพลาด เช่น บันทึกเวลาขนส่งรับพัสดุก่อนเวลาอนุมัติการชำระเงิน (คัดกรองทิ้ง 1,373 แถว ข้อมูลสมบูรณ์พร้อมวิเคราะห์สุทธิ 95,082 แถว)
- Date Normalization: ใช้ `.dt.normalize()` ในการเปรียบเทียบ `delay_days` เพื่อตัดเศษเวลาชั่วโมง/นาที/วินาทีออก และเปรียบเทียบความล่าช้าในระดับวันที่อย่างเป็นธรรม

### 4. Aggregation & Anti-Duplication Safeguards
- รวมคะแนนรีวิวต่อ 1 `order_id` ก่อนทำการเชื่อมโยงตาราง เพื่อป้องกันปัญหา Row Multiplication จากกรณีที่ลูกค้า 1 คนรีวิวสินค้าหลายชิ้นในออเดอร์เดียวกัน
- รวมยอดขายเฉพาะสินค้าของผู้ขายรายนั้นในแต่ละออเดอร์ (`groupby(["seller_id", "order_id"])`) ก่อนนำไปคำนวณมูลค่ายอดเงินที่ตกอยู่ในความเสี่ยง (Revenue at Risk) เพื่อไม่ให้เกิดปัญหานับยอดเงินซ้ำซ้อน

ชุดข้อมูลที่ถูกส่งออกไปยังโฟลเดอร์ `./output` ได้รับการจัดรูปแบบตามสถาปัตยกรรม Star Schema เพื่อเพิ่มประสิทธิภาพในการสร้าง Data Model และ Query Performance:

| ชื่อไฟล์ | ประเภท | รายละเอียดและคีย์เชื่อมโยง |
| :--- | :--- | :--- |
| `fct_orders_o2c.csv` | Fact Table | คำสั่งซื้อที่จัดส่งสำเร็จ พร้อมระยะเวลาแต่ละ Stage, สถานะส่งช้า, คะแนนรีวิว, รัฐปลายทาง และยอดเงินชำระ (`order_id`, `customer_id`) |
| `dim_state_summary.csv` | Dimension Table | สถิติภาพรวมรายรัฐ: จำนวนคำสั่งซื้อ, เวลาเฉลี่ย, อัตราส่งช้า, คะแนนรีวิวเฉลี่ย (`customer_state`) |
